# „Razem z ZD” – plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (wykonanie inline w tej sesji). Kroki `- [ ]`.

**Goal:** Osobny moduł HugMe dla osób z zespołem Downa i ich rodzin wg `docs/superpowers/specs/2026-10-03-razem-z-zd-design.md`.

**Architecture:** Blueprint `razem` + treści w `data/razem.py` (struktura grupa → etapy) + jedna tabela `family_requests`
dla wszystkich próśb oraz `events`/`event_signups`. Reużycie: `core.privacy.mask`, `core.notify`, `core.ai`, `catalog`,
makra `_macros.html`, panel `admin`.

**Tech Stack:** Python 3.12, Flask, Jinja, SQLite, pytest, Playwright + axe (audyt), vanilla JS tylko jako ulepszenie.

## Global Constraints

- Brak danych o zdrowiu i danych dziecka na serwerze; kalendarz wizyt tylko w localStorage.
- Każdy tekst od użytkownika przez `privacy.mask()` przed zapisem i przed AI.
- Brak danych osobowych w URL (pisma przez POST; kreator praw GET tylko z wartościami z białej listy).
- Wszystkie dane przykładowe fikcyjne i oznaczone „PRZYKŁAD”.
- CSP bez zmian: brak skryptów i stylów inline, JS z `/static`.
- WCAG 2.1 AA: axe 0 naruszeń na nowych widokach (desktop 1280 i 320 px), cele ≥ 44 px, etykiety, ETR.
- 2 commity (moduł; materiały), push tylko po zgodzie.

### Task 1: Dane i treści

**Files:** Modify `core/db.py`, `data/seed.py`, `data/seed_data.py`; Create `data/razem.py`; Test `tests/test_razem.py`

**Interfaces – Produces:**
- `data.razem.GROUPS: dict[str, dict]`; `GROUPS["zd"]["stages"]: list[dict]` z kluczami
  `slug, name, age, icon, now (list[3]), ask_doctor (list), documents (list), etr (str), innovations (list[str] tytułów)`.
- `data.razem.stage(slug) -> dict | None`
- `data.razem.REQUEST_KINDS: dict[str, str]` (kod → etykieta), `PUBLIC_KINDS = {"miejsce", "sprzet-oddam", "sprzet-przyjme"}`
- `data.razem.RIGHTS_QUESTIONS: list[(key, question)]`, `rights_result(answers: dict[str, bool]) -> list[dict(institution, why, documents)]`
- `data.razem.LETTERS: dict[slug, dict(title, fields: list[(name,label,hint)], template: str)]`
- Tabele: `family_requests(id, user_id, kind, powiat, stage, alias, title, body, status, matched_with, created_at)`,
  `events(id, title, powiat, date, place, body, created_at)`, `event_signups(event_id, user_id, created_at)`.

- [ ] Test: tabele istnieją; seed: ≥6 miejsc zatwierdzonych, 1 oczekujące, 4 ogłoszenia sprzętu, 4 wydarzenia, 3 „oferuje”,
  2 „szukam” (w tym para w wadowickim), ≥6 „dzien-specjalistow”; `GROUPS["zd"]` ma 6 etapów z wymaganymi kluczami;
  `rights_result({"orzeczenie": False, ...})` zawiera instytucję z orzeczeniem; maskowanie nie znajduje niczego w seedzie.
- [ ] Uruchom → FAIL. Implementacja. Uruchom → PASS.
